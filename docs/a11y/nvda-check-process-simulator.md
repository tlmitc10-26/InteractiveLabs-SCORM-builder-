# NVDA verification script: Process Simulator (Blank starter)

_Generated by `scripts/emit-nvda-script.mjs` from the same spec-determined transcript
data locked in `tests/sr-transcript-process.test.ts` (see `src/lib/a11y/transcript.ts`).
Do not hand-edit this file -- rerun `npm run a11y:script` to regenerate it after any
change to the runtime's markup or to the blank procedure starter config._

## Assumptions

- NVDA with **default settings** (default speech verbosity: roles and states announced).
- Latest Chrome or Firefox -- accname computation and live-region processing are the
  browser's job; NVDA reads whatever the browser exposes via the accessibility tree.
- Open **NVDA's Speech Viewer** before starting, so you can log/copy exactly what NVDA
  says as you go, and compare it word-for-word against the "NVDA should say" lines below.
- Load the Blank Procedure starter fresh (no prior SCORM resume/suspend data) before
  beginning at step 1.

## 1. Brief: live region, heading, Begin button

1. Read the first line → NVDA should say: **"0 of 3 required steps done"**
2. Press H → NVDA should say: **"Blank Procedure heading level 2"**
3. Press Tab → NVDA should say: **"Begin the procedure., button"**

## 2. Procedure room: Situation, Actions, and the action menu

4. Press Enter on "Begin the procedure." → NVDA should say the new heading:
   **"Procedure heading level 2"**
5. Continue reading → NVDA should say: **"Situation heading level 3"**
6. Continue reading (the opening situation text comes first) → NVDA should say:
   **"Actions heading level 3"**
7. Press Tab → NVDA should say: **"Describe the first action here, button"**
8. Press Tab → NVDA should say: **"Describe a second, gated action here, button"**
9. Press Tab → NVDA should say: **"Describe a third, independent required action here, button"**
10. Press Tab → NVDA should say: **"Describe a tempting but wrong action here, button"**

If you hear anything else here -- a different name, a missing "button" role word, a
stale label -- that's a contract regression: check
`tests/sr-transcript-process.test.ts`'s locked reading/focus-order transcripts against
what the runtime currently renders.

## 3. A legal action: the success-path focus contract, and a disabled button

11. Press Enter on "Describe the first action here" (its prerequisites, if any, are already
   met) → focus moves to the Situation panel's own heading (spec §3 review #1), NOT back to
   the action menu → NVDA should say: **"Situation heading level 3"**
12. Continue reading → NVDA should say the new situation-log entry, with its "Latest:"
   prefix (a visually-hidden, non-color-only cue -- spec §3 review #25):
   **"Latest: Describe what becomes true in the situation once this action is legally performed."**
13. Continue reading (or check the live region directly) → the progress line has already
   updated in the same beat: NVDA should say: **"1 of 3 required steps done"**
14. Continue reading down into the Actions menu → the just-completed action's OWN button
   is still in READING order (spec §3 review #5 -- only the TAB order drops it, asserted
   next) with its disabled state, which NVDA announces as **"unavailable,"** never the
   literal word "disabled":
   **"Describe the first action here, button, unavailable"**
15. Press Tab from the Situation heading → the completed action's button is skipped
   entirely (it dropped out of TAB order, though it stayed in reading order above) → NVDA
   should land directly on the next action:
   **"Describe a second, gated action here, button"**

If step 1 above didn't leave focus on the Situation heading -- e.g. NVDA reads the
"Situation" line only when you navigate to it manually -- that's a
focus-management regression: the runtime must move focus there itself on every successful
required action, never leave it on the now-disabled button.

## 4. An illegal attempt: the consequence panel replaces ONLY the action menu

16. Press Enter on any NOT-yet-done, illegal action (e.g. a distractor, or a required
   action whose prerequisites aren't all met yet) → the Situation panel and progress line
   persist untouched; ONLY the Actions sub-container is replaced by a consequence panel,
   and focus moves to ITS heading (spec §3 review #21/#26) → NVDA should say:
   **"Consequence heading level 3"**
17. Continue reading → NVDA should say the authored consequence text, then:
   **"Continue, button"**

The live region is NOT touched by this transition at all (its accessible name carries the
announcement instead, via the heading focus above) -- if you hear the progress count
re-announced here, that's a regression in the churn guard.

## 5. Continue: the menu rebuilds, focus returns to the attempted button BY ID

18. Press Enter on "Continue" → the action menu rebuilds in full, and focus lands back on
   the SAME button you attempted (spec §3 review #26) -- still enabled, since an illegal
   attempt never marks anything done → NVDA should say:
   **"Describe a tempting but wrong action here, button"**

## 6. Debrief: full log read-back, then the bundled step review

19. Complete every remaining required action in a legal order → the debrief is entered
   automatically, and focus moves to its own heading (no click needed to get there) → NVDA
   should say:
   **"3 of 3 required steps done"**
20. Move the browse cursor to the top of the debrief → NVDA should say: **"Procedure complete"**
21. Focus lands directly on the result heading → NVDA should say:
   **"Blank Procedure heading level 2"**
22. Continue reading → NVDA should say the score line, the announced source for the
   score (redundant with the aria-hidden numeral and quality chips above it):
   **"Steps: 3 of 3 clean. Attempts: 4 (expert minimum 3). Score: 90%."**
23. Press H → NVDA should say: **"Situation heading level 3"**
24. Continue reading the full situation log (it survives the transition to debrief in
   full -- spec §3 review #13, every entry re-rendered, not just the newest) → NVDA should
   say: **"Describe what becomes true in the situation once this action is legally performed."**
25. Continue reading the full situation log (it survives the transition to debrief in
   full -- spec §3 review #13, every entry re-rendered, not just the newest) → NVDA should
   say: **"Describe what becomes true once this action is legally performed."**
26. Continue reading the full situation log (it survives the transition to debrief in
   full -- spec §3 review #13, every entry re-rendered, not just the newest) → NVDA should
   say: **"Latest: Describe what becomes true once this action is legally performed."**
27. Press H → NVDA should say: **"Step review heading level 3"**
28. Continue reading the step review (bundled as ONE reading-order entry, same pattern
   as the other three engines' debrief lists) → NVDA should say, verbatim:
   **"Describe the first action here: completed on the first try. Describe a second, gated action here: completed on the first try. Describe a third, independent required action here: completed on the first try. Describe a tempting but wrong action here: attempted 1 time. Explain, for the debrief, why this action is never correct."**
29. Continue reading (or Tab; this is the only focusable control at debrief) → NVDA
   should say: **"Start over, button"**

## What you should NOT hear

- **Never the literal word "disabled"** -- a completed required action's button, while it
  stays in reading order (step 3 above), is announced as **"unavailable,"** the actual NVDA
  state word (see this script's `NVDA_STATE_WORD` table).
- **No re-announcement of the progress live region** when a consequence panel opens or
  closes -- its text changes ONLY on a completed required action or a reset (spec §3), never
  on an illegal attempt, asserted by `tests/sr-transcript-process.test.ts`'s churn guard.
- **No double announcement** of the Situation heading or the new log entry on a single
  successful action -- each transition updates the DOM exactly once (main.ts's `setText`
  churn guard and per-entry `<li>` append), so NVDA has nothing to re-announce.
- **Nothing announced as "clickable"** -- every action, Continue, Begin, and Start over is a
  native `<button>` element, never a generic `<div>`/`<span>` with a click handler bolted on.
- **No stray reading of the decorative done-glyph (✓) or the debrief's quality chips** --
  both are `aria-hidden="true"` and fully redundant with adjacent visible/announced text
  (the button's own disabled state above; the step review's own counts).
- **No terminal/dead-end state ever announced** -- an illegal attempt is always recoverable
  via Continue; nothing in this runtime's contract locks the learner out.
