# NVDA verification script: Case / Evidence Workspace (Blank starter)

_Generated by `scripts/emit-nvda-script.mjs` from the same spec-determined transcript
data locked in `tests/sr-transcript-case.test.ts` (see `src/lib/a11y/transcript.ts`).
Do not hand-edit this file -- rerun `npm run a11y:script` to regenerate it after any
change to the runtime's markup or to the blank case starter config._

## Assumptions

- NVDA with **default settings** (default speech verbosity: roles and states announced).
- Latest Chrome or Firefox -- accname computation and live-region processing are the
  browser's job; NVDA reads whatever the browser exposes via the accessibility tree.
- Open **NVDA's Speech Viewer** before starting, so you can log/copy exactly what NVDA
  says as you go, and compare it word-for-word against the "NVDA should say" lines below.
- Load the Blank Case starter fresh (no prior SCORM resume/suspend data) before beginning
  at step 1.

## 1. Brief: live region, heading, Open button

1. Read the first line → NVDA should say: **"Case file: 0 of 2 artifacts"**
2. Press H → NVDA should say: **"Blank Case heading level 2"**
3. Press Tab → NVDA should say: **"Open the case file., button"**

## 2. Workspace: open the case file, review an artifact, add it

4. Press Enter on the Open button → NVDA should say the new heading: **"Workspace heading level 2"**
5. Press Tab to the next artifact button → NVDA should say: **"Artifact OneText, button"**
6. Press Tab to the next artifact button → NVDA should say: **"Artifact TwoText, button"**
7. Continue reading → NVDA should say: **"Your case file heading level 3"**
8. Press Enter on the first artifact button ("Artifact OneText") → NVDA should say the new heading:
   **"Artifact One heading level 3"**
9. Continue reading (or Tab) → NVDA should say: **"Add as strong support, button"**
10. Continue reading (or Tab) → NVDA should say: **"Add as weak support, button"**
11. Press Enter on "Add as strong support" → the live region updates: NVDA should say:
   **"Case file: 1 of 2 artifacts"**
12. Continue reading the case-file panel → NVDA should say the strength text: **"Strong support"**
13. Continue reading (or Tab) → NVDA should say: **"Remove from case file, button"**

## 3. Conclude: choose a conclusion, select a reason

14. Press Enter on "Ready to conclude" → NVDA should say the new heading:
   **"Conclude heading level 2"**
The two conclusion radio buttons follow, initially unchecked:

15. Continue reading (or Tab) → NVDA should say: **"Conclusion A, radio button, not checked"**
16. Continue reading (or Tab) → NVDA should say: **"Conclusion B, radio button, not checked"**
17. Continue reading → NVDA should say: **"Submit conclusion, button, disabled"**
18. Press Space/Enter on "Conclusion A" → NVDA should say it flip to checked:
   **"Conclusion A, radio button, checked"**
19. Focus moves automatically to the newly revealed reason group's legend (NOT announced
   via the live region -- spec §3's aria-describedby doctrine) → NVDA should say:
   **"Which of these justify Conclusion A? Select all that apply."**
20. Continue reading (or Tab) → NVDA should say: **"A sound reason that genuinely follows from the evidence for Conclusion A., check box, not checked"**
21. Continue reading (or Tab) → NVDA should say: **"A plausible-sounding but flawed reason for Conclusion A., check box, not checked"**
22. Press Space on the first reason checkbox → NVDA should say it flip to checked:
   **"A sound reason that genuinely follows from the evidence for Conclusion A., check box, checked"**
23. Continue reading → the Submit button is no longer disabled: NVDA should say just:
   **"Submit conclusion, button"**

## 4. Debrief: score, case-file comparison, reason review

24. Press Enter on "Submit conclusion" → the live region reflects the final case file:
   NVDA should say: **"Case file: 1 of 2 artifacts"**
25. Move the browse cursor to the top of the debrief → NVDA should say: **"Case complete"**
26. Focus lands on the result heading (the chosen conclusion's label) → NVDA should say:
   **"Conclusion A heading level 2"**
27. Continue reading → NVDA should say the score line: **"Evidence: 1 of 1. Reasoning: 1 of 1. Conclusion credit: full. Score: 100%."**
28. Press H → NVDA should say: **"How your case file compares heading level 3"**
29. Continue reading the comparison list (bundled as ONE reading-order entry) → NVDA
   should say, verbatim:
   **"Artifact One: included in your case file. This supports the conclusion."**
30. Press H → NVDA should say: **"Your reasoning heading level 3"**
31. Continue reading the reason-review list (bundled as ONE reading-order entry,
   including the flaw note for any flawed reason the learner selected) → NVDA should say,
   verbatim:
   **"A sound reason that genuinely follows from the evidence for Conclusion A.: selected. This reasoning holds up. A plausible-sounding but flawed reason for Conclusion A.: not selected. Good: this reasoning has a flaw."**
32. Press H → NVDA should say: **"Expert's rationale heading level 3"**
33. Continue reading (or Tab; this is the only focusable control at debrief) → NVDA
   should say: **"Start over, button"**

## What you should NOT hear

- **No double announcement** of a conclusion's checked state or the case-file status --
  each change updates the DOM exactly once (main.ts's churn guard on the one live region),
  so NVDA has nothing to re-announce on a no-op re-render.
- **No live-region announcement of the reason group appearing** -- choosing a conclusion
  moves focus directly to the reason group's legend (see step 3 above); the case-file
  status live region is untouched by conclusion/reason selection at all
  (`tests/sr-transcript-case.test.ts`'s "exactly one live region" contract).
- **Nothing announced as "blank"** -- every artifact button, radio, and checkbox has a
  non-empty accessible name (the artifact title + kind, the conclusion label, the reason
  text), never an empty or icon-only label.
- **Nothing announced as "clickable"** -- every control is a native form element (button/
  radio/checkbox), never a generic `<div>`/`<span>` with a click handler bolted on.
- **No stray reading of the decorative reviewed glyph** (the artifact list's ●/○ mark) --
  it is `aria-hidden="true"` and excluded from the reading order; only the case-file
  status live region ever reports how many artifacts have been reviewed/added.
- **No flaw note read aloud before submission** -- a flawed reason's explanation only
  appears in the debrief's reason-review list, never as part of the Conclude-step
  checkbox's own accessible name.
