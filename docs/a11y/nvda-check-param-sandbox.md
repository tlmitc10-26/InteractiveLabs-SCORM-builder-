# NVDA verification script: Parameter Sandbox (Buoyancy Explorer starter)

_Generated by `scripts/emit-nvda-script.mjs` from the same spec-determined transcript
data locked in `tests/sr-transcript.test.ts` (see `src/lib/a11y/transcript.ts`).
Do not hand-edit this file -- rerun `npm run a11y:script` to regenerate it after any
change to the runtime's markup or to the buoyancy starter config._

## Assumptions

- NVDA with **default settings** (default speech verbosity: roles and states announced).
- Latest Chrome or Firefox -- accname computation and live-region processing are the
  browser's job; NVDA reads whatever the browser exposes via the accessibility tree.
- Open **NVDA's Speech Viewer** before starting, so you can log/copy exactly what NVDA
  says as you go, and compare it word-for-word against the "NVDA should say" lines below.
- Load the Buoyancy Explorer starter fresh (no prior SCORM resume/suspend data) before
  beginning at step 1.

## 1. Tab through the controls (focus order)

Starting from before the sandbox (e.g. the browser's address bar), press Tab repeatedly:

1. Press Tab → NVDA should say: **"Object mass (kg), slider, 5"**
2. Press Tab → NVDA should say: **"Object mass, exact value, spin button, 5"**
3. Press Tab → NVDA should say: **"Fluid (kg/m3), combo box, Fresh water"**

If you hear anything else here -- a different name, a wrong role word, a stale value --
that's a contract regression: check `tests/sr-transcript.test.ts`'s locked focus-order
transcript against what the runtime currently renders.

## 2. Headings and the chart image

Use NVDA's quick-navigation heading key (`H`) or browse the page top to bottom:

4. Press H → NVDA should say: **"Buoyancy Explorer heading level 2"**
5. Press H → NVDA should say: **"Challenges heading level 2"**
6. Navigate onto the chart → NVDA should say: **"Volume vs mass chart, graphic"**
   - Note: this generation environment (jsdom) has no real `<canvas>` 2D context, so
     the label above is the chart's STATIC initial label. In a real browser the label
     is DYNAMIC and includes the plotted axis range and current point, e.g. something
     like “Volume vs mass chart: x from 0.5 to 20, y from 0.5 to 20, current point
     (5, 5)”. Verify the dynamic form manually in the browser; only its STATIC form is
     covered by the automated contract (see the comment in `tests/sr-transcript.test.ts`
     group 2).

## 3. The outputs summary (debounced live region)

At the default values (mass 5 kg, Fresh water), after you stop interacting for about
half a second, NVDA should announce:

7. Wait ~500ms with no input → NVDA should say: **"Displaced volume: 5. Weight (gravity): 49.1"**

This does NOT fire on every keystroke/drag tick -- only once, ~500ms after input settles.
If you hear it announced repeatedly while dragging, that's a regression in the debounce.

## 4. Arrow the mass slider up to the challenge threshold

Tab to the mass slider (step 1 above) and press the Right Arrow key repeatedly:

8. Press Right Arrow → NVDA should say (bare number only, no name/role repeated):
   **"5.5"**
9. Press Right Arrow → NVDA should say (bare number only, no name/role repeated):
   **"6"**
   - At this exact key press the challenges live region also updates. Because it is
     a non-atomic `aria-live="polite"` region, NVDA announces each changed text node
     separately (in DOM order), essentially at the same time as the slider's own
     number above -- you may hear it interleave with, or immediately follow, the
     bare-number announcement. That overlap is expected AT behavior, not a defect.
   - Also expect to hear: **"Score: 100% — 1 of 1 challenges met. Lesson complete. (preview — grades record only in the course)"**
   - Also expect to hear: **"Met"**

## 5. Wait for the outputs summary to catch up

10. Stop interacting and wait ~500ms → NVDA should say:
   **"Displaced volume: 6. Weight (gravity): 58.9"**

## What you should NOT hear

- **No double announcement** of the same value/text within the same ~500ms window --
  `tests/sr-transcript.test.ts`'s churn guard proves the runtime never rewrites a live
  region's text node when the computed text hasn't actually changed, so NVDA has nothing
  to re-announce on a no-op re-render.
- **Nothing announced as "blank"** -- every focusable control in step 1 has a non-empty
  accessible name (a paired `<label for>`, or an explicit `aria-label` for the slider's
  companion exact-value field).
- **Nothing announced as "clickable"** -- every control is a native form element (range/
  number/select), never a generic `<div>`/`<span>` with a click handler bolted on, so NVDA
  never falls back to its generic "clickable" description.
- **No stray reading of the decorative challenge-met glyph mark or any decorative image**
  -- both are `aria-hidden="true"` and are excluded from the reading order (see
  `tests/sr-transcript.test.ts` group 4).
